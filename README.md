# 릴레이소설 💌

**두 사람이 번갈아 소설을 쓰는 아주 간단한 웹사이트.**

- 소설 제목과 **두 사람의 이름**을 적으면 바로 시작
- 첫 번째 사람이 장면을 쓰고 **글 저장하고 상대에게 보내기**를 누름
- 휴대폰 공유 시트(지원 시)에서 카카오톡 등 원하는 앱으로 **최신 링크**를 전달
- 받은 사람은 링크를 열고 두 번째 장면을 쓴 뒤 다시 **새 링크**를 전달
- 휴대폰에서 보기 쉬운 큰 글쓰기 창, 이전 장면 카드, 다음 차례 표시
- 작성 중인 원고 브라우저 자동 임시 저장
- Markdown 원고 저장 및 JSON 백업/불러오기
- 전에 작성한 작품 데이터는 로컬 저장소에서 계속 불러오도록 구현

## 접속

GitHub Pages: **https://ddogy1212.github.io/relay/**

## 2인용 이용 방법

1. 한 명이 작품 제목, 내 이름, 상대 이름을 입력해 시작합니다.
2. 이번 차례인 사람이 원고를 작성해 저장합니다.
3. 공유 화면에서 최신 링크를 친구에게 보냅니다.
4. 다른 사람은 받은 링크를 열고 이어 작성합니다.
5. 이후에도 **장면을 새로 쓸 때마다 최신 링크를 다시 공유**합니다.

누가 이번 차례인지 크게 표시해 줍니다. 기존 이름이 잘못 표시되면 작품 제목 아래의 **이 기기 작가 · 바꾸기**를 누르세요.

## 꼭 알아둘 점

이 버전은 **서버 없는 링크 전달 방식**입니다.

- **실시간 협업 또는 자동 동기화가 아닙니다.** 오래된 링크를 열면 예전 원고만 보입니다.
- 사용자 이름으로 쓰는 순서를 관리할 뿐, **로그인/2인 전용 접근 권한 검증**은 없습니다. 링크를 받은 누구나 그 링크에 포함된 작품을 읽을 수 있으므로 민감한 개인정보는 쓰지 마세요.
- 링크에 원고를 압축하여 담습니다. 내용이 길어지면 링크 대신 **JSON 백업 파일**을 상대에게 보내야 할 수 있습니다.
- 데이터는 각자의 브라우저 \`localStorage\`에 저장됩니다. 브라우저 데이터를 지우거나 기기를 바꾸기 전 JSON 파일로 백업하세요.
- 두 사람이 동시에 서로 다른 사본을 수정해 버전이 갈리면 다른 작품으로 보관합니다. 가장 최근 전달받은 원고를 기준으로 이어 쓰는 것이 좋습니다.

## 개발과 테스트

외부 프런트엔드 라이브러리가 필요 없는 정적 사이트입니다.

\`\`\`bash
node --check app.js
node tests/smoke.cjs
\`\`\`

GitHub Actions에서 위 검증을 먼저 실행한 후 GitHub Pages에 배포합니다.

## 파일 구조

- \`index.html\` — 화면 및 사용 흐름
- \`styles.css\` — 모바일 우선 디자인
- \`app.js\` — 2인 차례/임시저장/링크 전달/백업
- \`tests/smoke.cjs\` — 두 기기의 릴레이 작성 모의 테스트
- \`.github/workflows/deploy.yml\` — 테스트 및 배포

## 상대가 아직 이어 쓰지 않았다면?

내가 쓴 뒤 상대 차례를 기다리는 동안 **'💌 이어 써 달라고 톡 보내기'** 버튼이 나타납니다. 누르면 현재 원고 링크와 가벼운 안내 메시지를 휴대폰 공유 메뉴(또는 복사)로 보낼 수 있습니다. **직접 누르고 수신자를 선택해야 보내지며 자동 발송은 아닙니다.**

이 사이트는 공용 서버와 실시간 동기화가 없으므로 상대가 실제로 작성했는지, 읽었는지 알 수 없고 자동 푸시 알림도 발송할 수 없습니다. 자동 알림을 원한다면 로그인, 실시간 데이터 저장소, 푸시 구독과 알림 서비스의 별도 구현이 필요합니다.
